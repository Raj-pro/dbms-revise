View Serializability

Compare read-from relationships and final writes to determine view equivalence.

1. What is view serializability?

Two schedules are view-equivalent when they preserve the same key relationships:

Initial reads

If a transaction reads the initial value of X in one schedule, it must do so in the other.

Read-from relation

If Ti reads X written by Tj in one schedule, the same transaction must read X from the same writer in the other.

Final write

The transaction performing the final write of each data item must be the same in both schedules.

2. Conflict vs. view serializability

Conflict serializabilityView serializability
Based on order of conflicting operation pairs.Based on initial reads, read-from relationships, and final writes.
Can be checked with a precedence graph.More difficult to test in general.
Every conflict-serializable schedule is view-serializable.Some view-serializable schedules are not conflict-serializable, often because of blind writes.

4. Three conditions — worked checklist

When comparing two schedules, complete these checks for each data item:

  1. Who reads the initial value?
  2. For each read, which transaction wrote the value being read (if any)?
  3. Who performs the final write?
Important: A schedule is view-serializable if it is view-equivalent to at least one serial schedule. Merely having the same final database values is not enough.

Exam recap

  • View equivalence preserves initial reads, read-from relationships, and final writes.
  • View serializability means view-equivalent to some serial schedule.
  • Conflict serializability implies view serializability, but the reverse is not always true.
  • Blind writes explain many schedules that are view-serializable but not conflict-serializable.
