SQL Queries and Nested Queries

Explore SQL clauses, subqueries, EXISTS, NOT EXISTS, and how SQL expresses data requests.

1. SQL query structure

SQL is mainly declarative: you describe the result you want, and the database chooses an execution plan.

SELECT Dept, COUNT(*) AS Total
FROM STUDENT
WHERE Year >= 2
GROUP BY Dept
HAVING COUNT(*) > 1
ORDER BY Total DESC;
ClausePurpose
SELECTChoose output columns or expressions
FROMChoose source tables
WHEREFilter rows before grouping
GROUP BYGroup rows by values
HAVINGFilter groups after aggregation
ORDER BYSort the output

2. Nested query

A query inside another query. It can return one value, a list of values, or a table depending on its form.

SELECT Name
FROM STUDENT
WHERE Dept IN (
  SELECT Dept
  FROM DEPARTMENT
  WHERE Campus = 'North'
);

3. EXISTS and NOT EXISTS

EXISTS is true if its subquery returns at least one row. NOT EXISTS is true if it returns no rows.

SELECT s.Name
FROM STUDENT s
WHERE EXISTS (
  SELECT 1 FROM ENROLLMENT e
  WHERE e.StudentID = s.StudentID
);

These are often used for “has at least one” and “has none” queries.

4. Correlated subquery

A correlated subquery refers to a column from the outer query. Conceptually, its condition depends on the current outer row.

SELECT s.Name
FROM STUDENT s
WHERE EXISTS (
  SELECT 1 FROM ENROLLMENT e
  WHERE e.StudentID = s.StudentID
);

Here, s.StudentID comes from the outer query.

5. SQL and relational calculus

Relational calculus describes the logical condition a result must satisfy. SQL often expresses similar requests using SELECT, WHERE, EXISTS, and other clauses.

Logic condition → SQL predicate

SQL is not simply identical to classical relational calculus: SQL supports bags (duplicates), NULL, aggregation, ordering, and other features.

Exam reminder

  • WHERE: filters rows.
  • HAVING: filters groups.
  • IN: checks membership in a set of values.
  • EXISTS: checks whether at least one row exists.
  • NOT EXISTS: checks whether no matching row exists.
