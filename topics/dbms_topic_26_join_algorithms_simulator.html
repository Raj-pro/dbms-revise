1. What does a join do?

A join combines rows from two relations based on a condition, commonly matching a key in one table with a foreign key in another.

AlgorithmCore operationTypical strength
Nested-loopCompare each row of one input with rows of the other.Simple; works with any join condition and small inputs.
Block nested-loopRead a block of outer rows, then scan the inner input for that block.Reduces repeated I/O versus row-at-a-time nested loops.
Index nested-loopFor each outer row, probe an index on the inner join key.Good when outer input is small and inner index is useful.
Sort-mergeSort both inputs by join key, then scan them together.Useful for sorted inputs and some range/equality joins.
Hash joinBuild a hash table on one input and probe it with the other.Often efficient for equi-joins when memory and conditions suit.

Exam recap

  • Nested-loop: simple; can be expensive for large inputs.
  • Block nested-loop: processes groups of outer rows to reduce scans.
  • Index nested-loop: probes an inner index for each outer row.
  • Sort-merge: sort then merge by key; already-sorted data helps.
  • Hash join: build and probe; typically for equality joins.
  • The optimizer chooses based on estimated I/O, CPU, memory, indexes, and statistics.
