Database Transactions

Learn transaction operations, transaction states, and why databases treat work as a logical unit.

1. What is a transaction?

A transaction is a sequence of database operations treated as one logical unit of work. It may read data, modify data, and then either commit the changes or roll them back.

Example: bank transfer

Transfer ₹500 from Account A to Account B: subtract ₹500 from A and add ₹500 to B.

Why a transaction?

Both changes should succeed together. If the second update fails, the first must not remain as a partial transfer.

Basic commands

BEGIN starts a transaction; COMMIT makes changes permanent; ROLLBACK undoes uncommitted changes.

3. Transaction states

A transaction commonly passes through these states:

StateMeaning
ActiveOperations are executing.
Partially committedThe final statement has executed, but commit completion/durability is not yet fully assured.
CommittedThe transaction completed successfully; its changes are committed.
FailedThe transaction can no longer proceed normally because of an error or failure.
AbortedThe system has undone its effects; it may be restarted or terminated.
TerminatedThe transaction has left the system after commit or abort.
Simple path: Active → Partially committed → Committed → Terminated. If an error occurs: Active → Failed → Aborted.

Exam recap

  • A transaction is a logical unit of database work.
  • COMMIT completes the transaction successfully.
  • ROLLBACK undoes uncommitted changes.
  • Transactions have states such as active, failed, aborted, committed, and terminated.
  • Transactions help preserve database correctness; ACID properties explain their key guarantees and are the next syllabus topic.
