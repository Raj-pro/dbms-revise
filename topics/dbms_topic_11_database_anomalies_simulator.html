1. What is a database anomaly?

A database anomaly is an unwanted problem when inserting, deleting, or updating data in a poorly organized table. Anomalies often happen because the same fact is stored repeatedly.

Simple idea: If department information is repeated in every student row, changing one department name may require changing many rows. Missing one row creates inconsistent data.

3. Understand the three anomalies

Insertion anomaly

You cannot add a new course unless you also invent a student record, because the table combines course and student information.

Example: Course C3 is planned, but no student has enrolled yet.

Deletion anomaly

Deleting one row unintentionally removes other information that should be kept.

Example: If Meera is the only student enrolled in C2, deleting her row also loses the only stored details about Networks and Dr Sen.

Updation anomaly

The same fact appears in multiple rows, so all copies must be changed together.

Example: If Dr Rao's name changes, both rows for DBMS must be updated.

How normalization helps

Split information into related tables such as STUDENT, COURSE, and ENROLLMENT, using keys to connect them.
