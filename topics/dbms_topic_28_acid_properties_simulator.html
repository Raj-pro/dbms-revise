ACID Properties

Understand the four guarantees that help transactions preserve correct database behavior.

1. The four ACID properties

Atomicity

All operations in a transaction happen, or none of them do. Prevents partial updates.

Memory aid: All or nothing.

Consistency

A transaction takes the database from one valid state to another, preserving defined constraints.

Memory aid: Rules remain satisfied.

Isolation

Concurrent transactions should not interfere in ways that violate the selected isolation guarantees.

Memory aid: Safe concurrent work.

Durability

After a successful commit, changes survive crashes according to the DBMS's durability guarantees.

Memory aid: Committed means retained.

4. ACID vs. common problems

ProblemRelevant propertyReason
Only the debit happens; credit failsAtomicityBoth parts should be committed together or undone together.
A rule such as balance ≥ 0 is violatedConsistencyConstraints must hold before and after a successful transaction.
Concurrent transactions see or overwrite intermediate data improperlyIsolationConcurrency control governs which interleavings are allowed.
Committed data disappears after a crashDurabilityRecovery and persistent logging help preserve committed updates.
