Referential Integrity Constraints

Explore how databases keep relationships between parent and child tables valid.

1. The idea in simple words

Referential integrity keeps foreign-key references consistent. A child row's foreign-key value must refer to an existing key in the parent table, unless the foreign key is allowed to be NULL.

Referenced relation (parent)

Contains the key being referenced, such as DEPARTMENT(DeptID).

Referencing relation (child)

Contains the foreign key, such as STUDENT(DeptID).

Think of it like a rule: a student cannot refer to department D9 if D9 does not exist in the DEPARTMENT table.

4. ON UPDATE rules

Similar rules can apply when a referenced key value changes. For example, if department D2 is renamed to D20, the database must avoid leaving child rows with a broken reference.

ON UPDATE CASCADE

Changes matching foreign-key values in child rows automatically.

ON UPDATE NO ACTION / RESTRICT

Prevents or rejects a parent-key change that would violate the relationship, depending on database timing and implementation.
