Functional Dependency (FD)

Learn how one attribute or group of attributes determines another—with examples you can test.

1. The basic idea

A functional dependency describes a rule between columns in a table. If X → Y, then whenever two rows have the same value of X, they must also have the same value of Y.

X → Y

X is the determinant (the column(s) doing the determining). Y is the dependent attribute (the column(s) being determined).

Example: StudentID → StudentName. If StudentID is the same in two rows, StudentName must be the same too.

Important: an FD is a rule expected to hold for every valid state of the database—not merely a coincidence in a small sample.

2. Trivial FD

An FD X → Y is trivial when every attribute on the right is already included on the left: Y ⊆ X.

{A, B} → A
Always follows from set inclusion

Example: {StudentID, CourseID} → StudentID. StudentID is already part of the left side.

3. Non-trivial FD

An FD is non-trivial when the right side contains at least one attribute not present on the left: Y ⊄ X.

StudentID → StudentName
Right side adds new information

Example: StudentID → Department, assuming each student has one department in this database.

4. Semi-non-trivial FD

Often called partially non-trivial: the right side shares some attributes with the left, but also includes at least one new attribute.

{A, B} → {A, C}
Some overlap, some new

A is already on the left; C is new. So this FD is non-trivial overall, and more specifically partially non-trivial.

7. Quick practice

Q1. Is {A, B} → B trivial?

Q2. Is StudentID → StudentName non-trivial, assuming StudentName is not StudentID?

Q3. In {A, B} → {A, C}, which best describes the FD?

8. Remember this

  • X → Y: same X value means same Y value in every valid instance.
  • Trivial: all of Y is already contained in X.
  • Non-trivial: at least one attribute of Y is not in X.
  • Partially non-trivial: Y overlaps with X but also has a new attribute.
