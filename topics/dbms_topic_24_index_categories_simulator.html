Database Index Categories

Compare primary, clustering, and secondary indexes — plus dense and sparse indexes.

1. What is an index?

A database index is an extra data structure that helps the DBMS find rows faster. Think of a book index: it points you toward the page rather than making you read every page.

Benefit

Faster searches and often faster sorting or joins.

Cost

Extra storage and additional work when rows are inserted, updated, or deleted.

Important

An index usually stores search-key values and pointers/references to records or blocks.

3. Dense vs. sparse index

A dense index has an index entry for every search-key value or record (depending on the design). A sparse index has entries for only some values, commonly one per data block, and generally relies on the data being ordered.

4. Clustered vs. non-clustered (conceptual)

Clustered index

Rows are stored in an order related to the index key. This can make range scans efficient. A table can have only one physical row order.

Non-clustered index

The index is separate from the table's physical row arrangement and points to rows. Multiple non-clustered indexes may exist.

Do not automatically treat “primary/secondary” and “clustered/non-clustered” as identical pairs. They describe different aspects, and exact terminology depends on the DBMS/textbook.

Exam recap

  • Primary: on the file's ordering key.
  • Clustering: on an ordering field that can have repeated values.
  • Secondary: on a field that is not the physical ordering field.
  • Dense: entry for every search-key value/record, according to the index design.
  • Sparse: entries for only selected values/blocks; typically requires ordered data.
  • Trade-off: indexes speed up reads but consume storage and add write-maintenance overhead.
